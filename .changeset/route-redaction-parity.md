Route redaction matches paths case-insensitively, decodes them repeatedly (up to five changes), normalizes dot segments and repeated slashes, ignores matrix parameters, and accepts the brace syntax of takt-core-php (`{param}`, `{param?}`, `{param<regex>}`). A `<regex>` constraint must follow a restricted grammar: printable ASCII only, literals, `.` (any byte but `/`), `\d \D \w \W \s \S` (`\s` and `\S` ASCII-only), matching on the UTF-8 bytes of the segment as PCRE without `u` does, classes with a strict `-` and no empty class, alternation at the top level, `*` `+` `?` `{n}` `{n,}` `{n,m}` (n ≤ m ≤ 100) with at most two variable quantifiers per route and per segment, at most 100 characters, and no range spanning `/`. A route is also unusable when the sum over its segments of (variable quantifiers minus one) exceeds 1, or when it has more than one catch-all segment, so that matching cost stays bounded. A constraint outside it masks every matching path as `/[redacted]`, and a constrained segment over 256 UTF-8 bytes does too. A path that cannot be decoded is masked as `/[redacted]` when a route is configured. The new `redactUndecodablePaths: false` option (`data-redact-undecodable-paths="false"` on `takt.auto.js`) decodes it leniently instead, as takt-core-php does: an invalid escape stays as written and the path is still matched. A path still encoded after five decoding passes is always masked. When a path is masked, its query string and fragment are dropped too.

Breaking change for `@vskstudio/takt-core/server`: `createServerTakt` now refuses `http://` endpoints on every host, `localhost`, `127.0.0.1` and `[::1]` included. Use `https://` (for local development, a local https certificate).
